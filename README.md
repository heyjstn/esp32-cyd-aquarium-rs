# ESP32 CYD Aquarium in Rust

An idiomatic Rust port of `esp32-cyd-aquarium` for the ESP32-2432S028R, commonly called the Cheap Yellow Display or CYD.

The firmware targets the active `esp32-2432s028r` behavior from the C++ project: an autonomous aquarium rendered as an 80x106 dot grid on the 240x320 ILI9341 display. It includes fish and creature variants, animated water and plants, boids, autonomous and touch feeding, a clock with optional Wi-Fi/NTP sync, and ambient-light backlight control.

## Target hardware

| Function | Hardware | GPIO |
| --- | --- | ---: |
| Display | ILI9341 over SPI2 at 55 MHz | MOSI 13, SCLK 14, CS 15, DC 2 |
| Backlight | LEDC PWM, active high | 21 |
| Touch | XPT2046, bit-banged SPI | MOSI 32, MISO 39, SCLK 25, CS 33, IRQ 36 |
| Ambient light | ADC1 LDR input | 34 |

The display is rotated 180 degrees to match the tested CYD enclosure orientation. CYD clones can use different controllers, backlight polarity, or touch wiring.

## Rust architecture

The aquarium engine and rendering pipeline are ordinary host-testable Rust. ESP-IDF-specific drivers are isolated under `src/hw` and only compile for `target_os = "espidf"`.

| Area | Rust modules |
| --- | --- |
| Scene orchestration | `aquarium`, `fish`, `world` |
| Creature shapes and motion | `body`, `motion`, `vec2` |
| FastLED-compatible color/noise math | `color`, `math8`, `noise`, `tone` |
| Logical layers and TFT dot rendering | `layer`, `renderer`, `text` |
| Testable input/backlight policy | `touch`, `backlight` |
| ESP32 device integration | `hw/display`, `hw/touch`, `hw/light`, `hw/wifi_time`, `hw/store` |

See [docs/PORTING.md](docs/PORTING.md) for the source-to-Rust mapping and intentional scope.

## Prerequisites

Install Rust with `rustup`, then install the Espressif toolchain and build helpers:

```sh
cargo install espup ldproxy espflash
espup install
```

On Unix shells, load the environment generated by `espup` in every terminal:

```sh
. "$HOME/export-esp.sh"
```

The upstream [ESP-IDF Rust template](https://github.com/esp-rs/esp-idf-template) documents OS packages and current tool setup in more detail.

## Optional Wi-Fi and local time

The aquarium runs without Wi-Fi and uses the firmware build time as its fallback clock. To enable NTP:

```sh
cp cfg.toml.example cfg.toml
```

Edit `cfg.toml` with the SSID, password, and a POSIX timezone string. Leave the password empty for an open network; non-empty passwords use WPA2-Personal. The file is ignored by Git because it can contain secrets. After a successful sync, Wi-Fi is powered down and retried at the configured interval.

## Build and test

Run all host-side unit tests and lints:

```sh
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo fmt --all -- --check
```

Build the release firmware for the original ESP32 Xtensa target:

```sh
cargo build --target xtensa-esp32-espidf --release
```

The ESP-IDF version is pinned in `.cargo/config.toml`, and `Cargo.lock` is committed so firmware builds use reproducible dependency versions.

The curated population is recreated on every boot. Periodic NVS snapshots are still saved for source parity and diagnostics, but the default firmware intentionally does not restore them.

## Flash and monitor

Connect the CYD over USB and run:

```sh
cargo run --target xtensa-esp32-espidf --release
```

The configured runner invokes `espflash flash --monitor`. If more than one serial device is present, `espflash` asks which one to use.

Expected boot output includes the physical/logical geometry, auto-backlight reading, and either an NTP start message or `reason=no_wifi_credentials`.

## Port scope

This repository ports the standalone CYD firmware selected by the source project's default PlatformIO environment. The browser UI, HUB75 matrix drivers, MQTT, DMX, and external SCD40 environment mode are not part of that build and are intentionally not pulled into this firmware. Temperature, humidity, and CO2 remain fixed at the same CYD defaults.
